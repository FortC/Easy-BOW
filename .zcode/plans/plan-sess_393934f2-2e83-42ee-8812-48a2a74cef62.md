# EasyBow 1.1.0：剪贴板修复 + 图片真实嵌入文档 + 文档美化

## 三个问题的根因与方案

**① 附截图按钮失效**：`navigator.clipboard.read()` 需要 clipboard-read 权限，应用从未配置权限处理器 → 每次点击都落入 catch 报"无法读取剪贴板"。
修法：改走主进程 Electron `clipboard.read()`（新版 W3C 风格 API），新增 IPC `clipboard:readImage`，返回 PNG dataURL；渲染层 `normalizeImage` 已支持 dataURL 字符串，压缩逻辑复用。输入框 Ctrl+V 路径本来就可用，保留。

**② 图片只进了链接**：现有 15 个动作没有任何"嵌入图片"能力，模型只能把 URL 当文字 type。
修法：新增 `paste_image` 动作——主进程下载图片（`session.fetch` 带登录态，`data:`/失败走全局 fetch）→ `nativeImage` 解码转 PNG → `clipboard.write([new ClipboardItem({'image/png': Blob})])` → 可选先 click 聚焦（复用 type 的 trusted click）→ `webContents.paste()` 真实粘贴。文档平台的粘贴处理器会上传并嵌入真图。

**③ 文档美化**：新增 `paste_rich` 动作——模型输出 Markdown → 主进程转 HTML（新文件 `src/main/markdown.ts`，支持标题/加粗/斜体/列表/引用/分割线/链接/表格/代码块）→ `clipboard.write` 写 `text/html`+`text/plain` → `webContents.paste()`，文档里得到带样式的富文本（标题层级、列表、加粗关键数据）。粘贴在光标处不清空已有内容（`type` 的 Ctrl+A 清空行为在已有内容的文档里反而危险，规则里注明）。

**关键 API 事实（已验证 electron.d.ts）**：Electron 44 clipboard 是新版 `read()/write(ClipboardItem[])` 接口（无 readImage/writeImage/writeHTML）；`webContents.paste()` 存在；`session.fetch` 不支持 `data:` scheme（需全局 fetch 兜底）。

## 改动清单

### 1. 主进程剪贴板读图（修复①）
- `src/main/index.ts`：import clipboard；`ipcMain.handle('clipboard:readImage')` → `clipboard.read()` 找 `image/png` 类型 → `getType('image/png')` → Blob→Buffer→dataURL；无图返回 null
- `src/preload/index.ts`：`readClipboardImage: () => ipcRenderer.invoke('clipboard:readImage')`
- `src/shared/types.ts`：`EasybowApi.readClipboardImage(): Promise<string | null>`
- `src/renderer/.../TaskPanel.tsx`：`pickClipboardImage` 改调 bridge（dataURL → `normalizeImage(str)`），空则提示无图；移除必失败的 `navigator.clipboard.read()` 主路径

### 2. 新增 markdown.ts（支撑③）
- 新文件 `src/main/markdown.ts`：`mdToHtml(md): string`（标题/粗斜体/行内代码/代码块/无序有序列表/引用/hr/链接/简单表格）+ `mdToPlain(md): string`；纯 TS 无依赖

### 3. 新动作 paste_image / paste_rich（②③）
- `src/shared/types.ts`：ActionName 加 `'paste_image' | 'paste_rich'`（字段 url/text/index 已有）
- `src/main/executor.ts`：
  - 抽 `focusTarget(t, index)` 复用 type 的"resolve→click 聚焦"段（type 改用之）
  - `case 'paste_image'`：URL 规范化（协议相对补 https、相对地址按页面 URL）→ data: 用全局 fetch / http(s) 先 `t.view.webContents.session.fetch` 再全局 fetch 兜底 → `nativeImage.createFromBuffer`（isEmpty 报错给模型）→ `toPNG()` → `clipboard.write([new ClipboardItem({ 'image/png': new Blob(...) })])` → 可选 focusTarget → `t.view.webContents.paste()` → sleep 800ms → result 报告尺寸（"已嵌入图片 WxH，若文档未显示请检查编辑焦点"）
  - `case 'paste_rich'`：`{{记忆键}}` 替换（同 type）→ mdToHtml/mdToPlain → `clipboard.write([new ClipboardItem({ 'text/html': html, 'text/plain': plain })])` → 可选 focusTarget → paste → result
  - 下载支持 ctx.signal 中断 + 20s 超时
- `src/main/agent/runner.ts`：lastResults 回传条件加 `paste_image | paste_rich`
- `src/main/agent/prompts.ts`：
  - 动作行两条（如上所述）
  - 新规则 12「文档写作」：空白文档默认 paste_rich 美化（# 标题、## 小节、列表、**加粗**、概览段）；图片必须 extract_images → paste_image 嵌入，禁止把图片 URL 当文字输入；type 会先清空目标、不能覆盖已有内容的场景用 paste_rich（光标处粘贴不清空）
- `TaskPanel.tsx` `actionChip`：两个新动作的标签（📝富文本 / 🖼嵌图）

### 4. 自测 + fixture
- `resources/testpage.html`：新增 `<div id="rich-area" contenteditable="true">` 富文本测试区
- `src/main/selftest.ts` 新增 4 项：
  1. Markdown 转换（h1/li/strong/table 输出正确）
  2. paste_rich E2E：executeBatch 聚焦 contenteditable → paste_rich → innerHTML 含 `<h1>`/`<li>`
  3. paste_image E2E：data: PNG → paste_image → contenteditable 出现 `<img`
  4. 剪贴板读图 IPC 往返：写一张图 → UI 上下文调 `window.easybow.readClipboardImage()` → 非空且为 dataURL（会临时占用剪贴板，自测模式可接受）
- `README.md`：功能表 + 动作说明 + 版本日志

## 明确不做
- 不做原生 Ctrl+V CDP 合成（CDP key event 不触发系统剪贴板粘贴，webContents.paste() 才是正路）
- 不做把 webp/gif 动图保真嵌入（nativeImage 统一转 PNG 静态帧）
- 不引入 markdown 三方库（自写子集转换器，零依赖）
