# EasyBow — AI 浏览器助手桌面应用（EXE）

## 总体架构

Electron 桌面应用：顶部页签栏（**最多 5 个页签**，独立持久登录态），中部左侧内置浏览器（WebContentsView），右侧 AI 任务面板（React UI，全中文）。TypeScript 主进程原生实现 agent 循环（browser-use 技术），**本地免费 OCR 按需兜底**，支持**跨页签数据搬运**，针对**淘宝/小红书/聚水潭等复杂真实站点**做了专项适配。

```
┌────────────────────────────────────────────────────────────┐
│ [页签1 淘宝][页签2 聚水潭][页签3]…(≤5)  +                   │
├────────────────────────────────────────────┬──────────────┤
│  地址栏  ← → ⟳                    [人工接管]│ 任务输入框    │
│                                            │ [开始][暂停][停止] │
│   当前页签浏览器视图                         │──────────────│
│   ↑ CDP 真实事件（trusted，非 JS 注入）     │ 操作过程时间线 │
│   ↑ 同源 iframe 穿透 · 本地 OCR             │  ·「页签1 读取到 3 条订单」│
│                                            │  ·「切到页签2 输入[3] A1024」│
│                                            │──────────────│
│                                            │ 任务记忆·Token统计│
└────────────────────────────────────────────┴──────────────┘
```

## 技术栈

- **Electron（最新稳定版）+ electron-vite + TypeScript + React**（UI 全中文）
- **LLM 双协议**（自定义 baseURL，兼容 DeepSeek/GLM/Kimi/OpenRouter/Ollama 等）：`openai` SDK + `@anthropic-ai/sdk`
- **本地 OCR**：PP-OCRv4 ONNX 模型经 `onnxruntime-node` 本地推理（免费离线，中文精度强）；打包遇阻回退 Windows 系统 OCR
- **打包**：electron-builder → NSIS 安装包 + portable 便携版（约 100~160MB）

## 核心设计

### 1. 多页签浏览器（≤5）+ 模型控制
- 每页签独立 WebContentsView + 独立 CDP 会话 + **独立持久分区**（登录一次长期有效）
- 每步提取当前活动页签可交互元素（可见性检查、视口优先、上限 80 个）：`[5] <button> "提交订单"`
- 动作集：`click / type / scroll / goto / back / wait / read_content / done` + `new_tab(url) / switch_tab(n) / close_tab(n)` + `save(key,value) / recall(key)`
- 弹窗→新页签、文件下载、页面崩溃恢复

### 2. 复杂真实站点适配（淘宝/小红书/聚水潭）
- **同源 iframe 穿透提取**：提取器递归进入同源 iframe（聚水潭老式布局必需）；跨域 iframe 走 CDP auto-attach 尽力支持
- **拟人化操作**：CDP 浏览器级真实输入事件（trusted，`navigator.webdriver=false`）、操作间隔随机化、拟人滚动；**慢速模式**可开（风控敏感站用）
- **人工接管模式**：检测滑块/验证码特征**自动暂停 + 系统通知**，人工完成后「继续」接着跑；可随时手动暂停接管
- **登录引导**：首次打开检测未登录自动提示，扫码/账密由用户手动完成
- 风险如实告知：不承诺全自动破解验证码；小红书高频自动化有账号风控风险，建议低频+人工监督

### 3. 跨页签数据搬运（A 页识别 → B 页填写）
- **任务记忆**：键值存储跨页签保持、不受历史压缩影响——搬运数据不丢失的核心保障；UI 面板可视化当前记忆
- **read_content()**：正文精简文本（表格自动转 Markdown，聚水潭订单表场景核心）；图片/canvas 数据走 OCR
- **type 支持多动作批**（点击→清空→输入连续执行），长文本用 `{{记忆key}}` 引用避免重复发送

### 4. 省 token（五层）
1. 模型只看编号元素列表，不发 HTML/截图（约 1~4k tokens/步，仅活动页签）
2. 元素上限 + 截断；历史压缩（近 3 步完整，更早一行摘要；任务记忆除外）
3. 每步多动作批输出，减少往返
4. **本地 OCR 替代视觉模型**：图片按钮补标签（+几十 token/个）；canvas/扫描件/图片内容 → OCR 文本（视觉模型 1~2k tokens/张 → 0 费用）；DOM 失败降级兜底
5. UI 实时真实 token 统计（API usage）；截图仅人看，默认不发模型

### 5. 看得见操作过程
- 实时时间线：思考摘要 + 动作标签（「页签1 读取 3 条订单」「切到页签2」「输入[3] A1024」）+ 页面变化 + 截图缩略图
- 暂停/停止（AbortController 中断请求）、任务记忆面板、token 计数

### 6. O/A 两家通用接口
- 设置页：协议（OpenAI 兼容 / Anthropic 兼容）+ baseURL + API Key（本地脱敏存储）+ 模型名
- 模型输出纯文本 JSON 宽松解析，不依赖 tool-calling，兼容性最大

## 实施步骤

1. **脚手架**：electron-vite React-TS、窗口、多页签管理、页签栏 + 地址栏（.npmrc 国内镜像）
2. **CDP 层**：debugger 附加、**同源 iframe 穿透**元素提取器、动作执行器（含页签/记忆动作）
3. **LLM 层**：设置界面 + 双协议 Provider（流式 + usage 统计）
4. **Agent 循环**：任务循环 + 任务记忆 + 时间线 UI + token 计数 + 暂停/停止
5. **站点适配**：验证码检测自动暂停 + 人工接管、拟人化/慢速模式、登录引导
6. **OCR 模块**：PP-OCR 流水线接入（图片按钮补标签 / 图片内容 / 降级兜底）
7. **健壮性**：弹窗→页签、下载、超时、崩溃、任务历史
8. **打包**：electron-builder、图标、EXE、中文 README（含三家站点实测指引）

## 已知限制（v1）
- 页签上限 5；跨域 iframe 尽力提取
- 滑块验证码走「自动暂停→人工→继续」，不自动破解；小红书建议低频使用
- OCR 每次约 100~500ms 本地推理（CPU 即可）
- 视觉模式默认关闭；OCR 打包失败时降级 Windows OCR
