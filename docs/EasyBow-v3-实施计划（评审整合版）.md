## 1. 横切约束（所有任务共同遵守，违反即返工）

1. **Prompt cache 布局（P1-12）**：W6/W7/W8/W10 的一切新增注入（反思段、delta 反馈、重规划说明、state 后缀）只允许出现在 `buildStepMessage` 的**动态后缀区**（缓存断点之后）；`SYSTEM_PROMPT` 与 `PLAN_SYSTEM_PROMPT` 保持字节稳定。本地 0.5B 链路（`LOCAL_SYSTEM_PROMPT`/`buildLocalPrompt`）**不加**任何新内容，A/B 对照后再议。
2. **mutation 分类表（P0-2）——W1 与 W10 共用一份常量**（新建 `src/main/domstable.ts`）：
   - **计入变动**：`childList`/`characterData` 结构性增删、`aria-*`、`disabled`、`checked`、`selected`、`value`、`hidden`、`role` 属性变化；
   - **忽略**：`style`、class 中纯动画/过渡类、轮播/广告容器选择器黑名单内的子树增删、自注入的 `data-easybow-*` 句柄属性。
   - 探针须覆盖穿透的每个 shadow root（P1-7）。
3. **失败三分类（P2-1）**：agent 失败计入成功率；环境失败（登录态过期/风控/网络中断/站点改版）单列不计入；产品 bug 单列建 issue。W11 报告与 W12 周报共用此口径。
4. **写操作安全**：提交/保存/删除/支付/下单类动作禁止裸坐标兜底（P0-1）；重规划过的任务 done 强制云端 L2（P0-5）——两处都是硬门禁，不可配置绕过。
5. **发布纪律不变**：新能力 settings 开关、默认开、可逐层关、独立回滚；`smartWaitFallback`（熔断回退）做内部状态即可，不暴露 UI。
6. **守住既有优势（评审第五章 7 条）**：本地 0.5B 混合模式、节点链 L0/L1/L2 + 填后语义校验、人机协作闭环、经验库、前缀缓存布局、拟人化输入、测试断言体系——回归集守护对象。

## 3. 任务卡（每卡：评审闭环点 / 改动点 / 验收 / 工期）

### T0 前置：step 计时埋点 + 基线采集（1 人日 + 3~5 自然日）

- **改动点**：telemetry 每步记录 `extractMs / axMs / llmMs / actMs / settleMs / shotMs` 分段耗时（P50/P90 可算）；
  `analyze-traces` 前身脚本先出「每步耗时分布 + 成功率」最小报表。
- **基线采集**：选 3 个真实高频任务（含聚水潭读单填淘宝、文档写作、表单录入），
  3~5 个自然日各跑 ≥10 次，**记录 P50/P90 步耗时、成功率、token/任务、重复失败率**——这组数就是验收表的「先测」基线。
- **验收**：报表能出 P50/P90；基线值填入第 5 节验收表。
- **工期**：1 人日 + 3~5 自然日（采集可与 T1 开发并行）。

### T1 W11 骨架：三任务回归 runner + 失败三分类报告（1.5 人日）

- **评审闭环**：P0-6（W11 顺序矛盾——统一为 W11 骨架先于 W1）、P2-1（三分类口径先立）。
- **改动点**：
  - 新建 `src/main/regression/`：runner（顺序跑 3 个任务型用例：自然语言任务 + 末尾 expect 验收）+ 报告 MD（成功率、失败三分类、P50/P90 步耗时、token）；
  - 3 个用例：本地 fixture 1 个（testpage 现有）+ 真实站点 2 个（登录态人工预热）；
  - 环境失败识别最小规则：验证码/登录页/网络错误命中即标 `infra` 不计入分子分母。
- **验收**：`npm run regression` 一条命令出报告；三分类列示正确。
- **工期**：1.5 人日（完整版见 T11）。

### T2 W1 智能等待（4 人日）——含 P0-2、P0-3 全部修正

- **评审闭环**：P0-2（熔断/首屏分策略/mutation 分类表/删保底 sleep）、P0-3（in-flight/未来监听/status/target）。
- **改动点**：
  1. 新建 `src/main/domstable.ts`：统一 mutation 分类表常量 + `waitDomStable`（覆盖 shadow root，忽略 `data-easybow-*`）；
  2. `cdp.ts`：in-flight 追踪（requestWillBeSent − loadingFinished/Failed，白名单 XHR/Fetch/Document）+ `waitNetworkQuiet`；
  3. `wait_for` 原语改**未来监听模式**：调用时注册 URL 匹配器（支持可选 method），等待**未来**出现的
     `loadingFinished` 且 status 2xx 才算等到；4xx/5xx **判该步失败**（进 T8 反思流程）；超时按 `seconds`；
  4. 提交类点击自动等待：网络静默 + DOM 静默 + **`Target.targetCreated` 监听**——点击打开新标签（预览/支付常见）
     时不等旧页静默，改为等新页 settle（上限顺延）；
  5. **自适应熔断**：同一任务连续 2 次吃满 settle 上限 → 该任务后续回退固定 600/1200ms，
     telemetry 记 `circuit_break` 事件与页面特征；`smartWait=false` 手动关闭（保留）；
  6. **首屏/动作后分策略**：首屏导航以 isLoading 结束 + 固定窗口为准（不套 mutation 静默）；
     mutation 静默仅用于动作批之后；慢速模式公式明确为 `实际等待 = max(拟人下限, min(信号等待, 上限))`；
  7. **删除保底固定 sleep**（现行批后 600ms）；慢速模式保留拟人下限。
- **验收**（T1 基线对照）：P50 步耗时降 ≥30% 且 **P90 不劣化**；持续动画 fixture 第 3 步起熔断且回退后 ≤ 现状值；
  提交返回 500 判失败不继续；提交开新标签正确等待新页；wait_for network 不受请求冲刷影响。
- **工期**：4 人日。

### T3 W2 开销削减（2 人日）——补 P90 卡点与坐标记录

- **评审闭环**：P1-11（并行化 P90 风险、截图策略、崩溃兜底、dpr）。
- **改动点**：
  1. 时间线截图分级：常规步缩略图（scale 0.5 + 低 q，**按 devicePixelRatio 换算保证观感**）；
     出错步/完成步高清；**每步零成本记录「点击坐标 + 目标 rect」**，时间线渲染命中叠加标记（定位诊断主手段，高清截图为辅）；
     渲染进程崩溃/executed 不返回 → smart 模式留错误帧兜底；
  2. AX 并行化：fetchAxTree 与 extract/截图进同一 `Promise.all`；盒子批 10→25 **但错开拟人输入动画窗口**（避免 raf 抢占）；
  3. 批尾与批间等待去叠加（humanDelay 与 settle 不重复计）；read_content 阅读停顿上限 1500→900ms。
- **验收**：非 LLM 单步开销 P50 < 800ms **且 P90 不劣于基线**；时间线命中标记可见；出错步有帧。
- **工期**：2 人日。

### T4 W3 结构化输出（2 人日）——补 P1-9 全部

- **评审闭环**：P1-9（预检探测不消耗真实请求、strict schema 工作量、Anthropic tool_use、国产端点覆盖）。
- **改动点**：
  1. **1-token 预检探测**：会话建立时（测试连接/任务首步前）探测 `json_schema`/`json_object` 支持，
     结果按 `baseURL|model` 缓存会话内粘滞——**不用真实任务请求做三级探测**；
  2. OpenAI 兼容：宽松 json_schema（全字段可空、不用 oneOf），strict 不可用自动降 `json_object`；
     DeepSeek/通义/智谱/vLLM 端点为降级链重点覆盖对象（自测加 mock 用例）；
  3. **Anthropic：tool_use + tool_choice 强制调用**实现 schema 输出（与 prompt cache 兼容），不再「保持现状」；
  4. 解析失败阈值 3→2 + few-shot 示例注入（保留原计划）。
- **验收**：解析失败步占比 <0.5%；探测阶段不产生计费任务调用（预检日志可见）。
- **工期**：2 人日。

### T5 W4 定位链（5~6 人日）——含 P0-1 全部修正，本期最重

- **评审闭环**：P0-1（容器锚点/坐标护栏/写操作禁裸坐标/state 时效）。
- **改动点**：
  1. **extract 记录容器锚点**：每个候选带最近稳定容器（`tr`/卡片/`fieldset`/列表项）的锚文本
     （同行订单号、卡片标题、legend）——`Candidate` 加 `anchor` 字段；
  2. **重定位链重排**：`path` → **容器锚点联合消歧**（`role+name ∧ anchor`，Playwright `filter({hasText})` 思路；
     CSS `:has()` / XPath ancestor 轴兜底）→ text/tag 中心点最近（**仅非列表场景**；同名重复>2 个时不启用）→ 同 role 就近；
     **虚拟列表**（节点回收）只走语义定位级；
  3. **④坐标兜底加命中护栏**：点击前 `elementFromPoint(x,y)` 校验最上层元素 tag/text 与目标一致，不一致放弃坐标法；
  4. **写操作禁裸坐标**：submitish 动作（提交/保存/删除/支付/下单）坐标兜底直接禁用（或强制人工确认），只允许语义定位；
  5. **state 时效**：快照带的 disabled/checked 是时点值，执行前实时属性再判一次（勾选/禁用类误判归零）；
  6. W11 fixture 增补（合入 T11）：同名按钮长列表、排序后列表、虚拟列表、懒加载 reflow 四类。
- **验收**：破坏测试页重定位 ≥90% **且必须含列表行操作用例**；
  列表排序/插新行后对指定锚文本行操作正确率 **≥95%，写操作错行 = 0**（错行即失败）；虚拟列表用例通过。
- **工期**：5~6 人日。

### T6 W5 Shadow DOM 穿透（2~3 人日）——含 P1-7 修正

- **评审闭环**：P1-7（复用现成递归、rect 不手工累加、探针覆盖 shadow、path 编码）。
- **改动点**：
  1. `EXTRACT_FN` collect 递归穿透 shadowRoot——**直接复用 `EXTRACT_IMAGES_FN` 已有的 shadow 栈递归模式**（`extractor.ts:607-618`）；
  2. **rect 不做 shadow host 偏移累加**（`getBoundingClientRect` 本身就是视口坐标；仅跨 iframe 需要坐标变换）——原方案该处设计作废；
  3. `domstable.ts` 探针安装到每个穿透的 shadow root（P0-2 分类表共用）；
  4. path 编码支持 shadow boundary（如 `12>3#0>5`），让 shadow 元素有首次点击快速路径；RESOLVE_FN/SET_VALUE_FN 等 walk 函数同步支持。
- **验收**：Lit/Vue 组件库 shadow 表单 fixture 全链路（提取/点击/输入/回读）可用；transform 缩放的弹层内元素坐标准确。
- **工期**：2~3 人日。

### T7 W10 动作后核验（2 人日）——含 P1-8 修正

- **评审闭环**：P1-8（假阴性/假阳性、动作类型分流、结构信号优先、零额外 CDP）。
- **改动点**：
  1. delta **按动作类型分流**：fill 比对 value 回读探针；toggle（click checkbox/switch）比对语义属性
     （与 T2 分类表同一份常量）；hover/toggle/toast 类**不给「无变化」强提示**（防假阴性误报）；
     仅「导航类/提交类 click + 全零 delta」给强提示，其余弱提示或不报；
  2. **结构信号优先**：`dialog 出现/新列表行/URL/标题变化` 权重高于候选数阈值；「候选数 ±30%」先只记 telemetry，
     跑一周分布再定阈值；
  3. **时序**：delta 复用**下一步开头 settle 后的 extract 快照**（与上一步快照对比），不额外提取——守「零额外 CDP」承诺；
  4. 反馈文案进动态后缀区（横切约束 1）。
- **验收**：遮挡点击 1 步内发现（原指标不变）；**toggle/fill/hover/toast 用例零误报**；每步 CDP 往返数不增。
- **工期**：2 人日。

### T8 W7 反思机制（2.5 人日）——含 P1-10 修正

- **评审闭环**：P1-10（签名含容器锚点、失败性质区分、清单边界）、P0-6（指标口径）。
- **改动点**：
  1. **失败签名 = 动作名 + 目标语义 + 容器锚文本**（复用 T5 锚点数据）——列表页 A 行「查看」失败不误伤 B 行「查看」；
  2. **失败性质二分**：**方式失败**（元素失效/未命中/遮挡）→ 进「禁止重复」清单；**业务失败**（提交后服务端报错、
     wait_for 网络 4xx/5xx）→ 可修正后重试（如改表单再提交），不进禁止清单；
  3. tried 清单边界：每目标保留最近 3 条、全局封顶 20 条；注入动态后缀区（横切约束 1）；
  4. 禁止第 3 次相同方式：执行前拦截并注入「换一种没试过的方式」提示；
  5. 本地 0.5B 链路不注入反思段（横切约束 1）。
- **验收**：指标口径 = **每个未达成目标的无效尝试次数（含执行前拦截、含换通道尝试）**，对比基线 **-50%**；
  列表多行同名按钮用例无误伤。
- **工期**：2.5 人日。

### T9 W8 动态重规划（3 人日）——含 P0-5 全部修正

- **评审闭环**：P0-5（节点重做/上下文继承/强制 L2/触发条件）。
- **改动点**：
  1. **已完成节点可标「需验证/需重做」**：重规划 prompt 明确「以当前页面真实状态为准，已失效的已完成步骤必须重做」，
     新计划允许把节点插回队首——治「登录被踢后已完成节点冻结死锁」；
  2. **上下文继承**：重规划 prompt 必须携带 原任务 + 已完成/待验证节点 + 当前失败节点 + 失败归因 +
     **tried 失败清单（T8）** + 当前快照摘要——防止新计划重蹈覆辙；
  3. **安全兜底（硬门禁）**：本任务发生过 ≥1 次重规划 → done 时**强制云端 L2 复核**（不允许本地复核放行、不允许 skip），
     复核不通过按重规划失败处理；
  4. **触发条件**：连续 3 步无任何节点推进 / 节点连续复核失败 2 次 / done 被拦且模型明确报告页面与预期不符；
     **删除**「步数过半 + 进度 <1/2」比例条件；
  5. 上限 2 次、时间线明示、重规划调用走 planner（T10 前先用主模型占位）。
